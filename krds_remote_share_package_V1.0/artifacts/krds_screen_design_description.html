사용자 흐름
  1. 사용자가 KRDS 메인 페이지에 진입한다.
  2. 디자이너, 개발자, 정부 관계자 중 자신의 역할을 선택한다.
  3. 선택한 역할에 맞는 튜토리얼, Figma, GitHub, 리소스, 체크리스트를 확인한다.
  4. 컴포넌트 또는 패턴을 검색하고 상세 문서에서 사용 기준과 접근성 조건을 확인한다.
  5. Figma 라이브러리 또는 HTML Component Kit을 실제 프로젝트에 적용한다.
  6. FAQ로 해결되지 않는 이슈는 문의 및 건의 채널로 전달한다.
Description
1 방문
  • KRDS 목적과 공식성을 즉시 인지할 수 있도록 공식 배너와 히어로 메시지를 제공한다.
  • 통합검색과 전체메뉴는 모든 화면에서 접근 가능해야 한다.
2 역할 선택
  • 디자이너, 개발자, 정부 관계자 진입점을 분리한다.
  • 각 역할 카드는 다음 행동을 명확하게 안내한다.
3 자산 활용
  • 디자이너는 Figma, 개발자는 GitHub/NPM/CDN, 관계자는 적용 사례와 체크리스트로 이동한다.
4 피드백
  • FAQ 확인 후 문의 및 건의로 이어지는 운영 흐름을 제공한다.

Description
1 공통 헤더
  • 문서 화면에서도 검색, 메뉴, 설정 기능을 유지한다.
  • 현재 메뉴는 시각적으로 구분하고 `aria-current` 의미를 갖도록 설계한다.
2 사이드 내비게이션
  • 컴포넌트 카테고리를 깊이 탐색할 수 있게 제공한다.
  • 선택/펼침 상태를 표시한다.
3 검색/필터
  • 컴포넌트명 검색과 유형 필터를 함께 제공한다.
  • 결과 없음 상태에는 철자 확인, 단어 분리, 일반 검색어 안내를 제공한다.
4 목록 항목
  • 한글명, 영문명, 유형, 요약 설명을 제공한다.
  • 상세 페이지 이동 링크 목적을 명확히 한다.
5 상세 템플릿
  • 컴포넌트 상세는 설계-개발 계약서로 취급한다.
  • 상태, 접근성, Figma property, CSS class, JS behavior를 대응시킨다.

Description
1 모바일 헤더
  • 로고, 메뉴, 검색을 최소 구성으로 유지한다.
  • 전체메뉴는 드로어 또는 전체 화면 메뉴로 전환한다.
2 히어로/CTA
  • 첫 화면에서 목적과 시작하기 버튼을 확인할 수 있게 한다.
  • 긴 문구는 2~3줄 안에서 줄바꿈한다.
3 역할 카드
  • PC의 3열 카드는 모바일에서 단일열 카드로 전환한다.
  • 터치 영역은 최소 44px 이상으로 설계한다.
4 하단 탐색
  • 모바일 핵심 이동 경로를 하단 탭바로 제공할 수 있다.
  • 현재 탭과 접근 가능한 이름을 명확히 한다.
공통 컴포넌트/상태 디스크립션
버전(ver) 1.0 페이지코드 KRDS-COMMON-DESC 페이지명 공통 상태/접근성 설명 페이지 5
No 대상 설계 디스크립션 상태/예외 접근성 기준
1 통합검색 헤더에서 항상 접근 가능한 검색 레이어를 제공한다. 메뉴명, 컴포넌트명, 패턴명, 문서 키워드를 검색 대상으로 본다. default, typing, results, no results, focus 검색 레이어 열림 시 입력 필드로 포커스 이동. Esc/닫기 버튼 지원.
2 글자·화면 설정 글자 크기 5단계와 기본/선명하게/시스템 설정 모드를 제공한다. 변경 값은 즉시 반영한다. default selected, font size changed, high-contrast, system 글자 확대 시 텍스트 겹침이 없어야 하며, 선명한 화면 모드에서 대비가 유지되어야 한다.
3 Figma 라이브러리 Style Guide, Components, Patterns, Icons와 Local Variables 구조를 확인하고 작업 파일에 라이브러리로 추가한다. light/high-contrast, large/small 컴포넌트 property와 문서 상태명이 대응되어야 한다.
4 디자인 토큰 Figma variable을 JSON으로 추출하고 CSS variable로 변환한다. Primitive는 직접 적용하지 않고 semantic을 사용한다. primitive, semantic, mode, responsive px to rem 변환 원칙과 `--krds` namespace를 유지한다.
5 컴포넌트 상세 정의, 사용 시점, 사용 금지, 구성 요소, 변형, 상태, 상호작용, 접근성, 코드, 관련 패턴을 포함한다. enabled, hover, pressed, focus, disabled, selected, error, success 모든 조작 컴포넌트는 접근 가능한 이름과 키보드 조작 기준을 가진다.
