1. 프로젝트 개요

KRDS는 공공 디지털 서비스 제작자가 같은 언어와 같은 자산으로 설계, 개발, 검수, 운영할 수 있도록 하는 정부 서비스 표준 UX/UI 플랫폼으로 역기획된다.

핵심 목적

국민에게 예측 가능하고 접근 가능한 디지털 정부 서비스 경험을 제공한다.

핵심 수단

Figma 라이브러리, 디자인 토큰, HTML Component Kit, 문서화 웹사이트를 연결한다.

핵심 사용자

디자이너, 개발자, 정부 관계자가 각자의 업무 맥락에서 KRDS를 적용한다.

문서 성격

내부 KPI, 예산, 조직, 일정은 공개자료로 확인할 수 없어 제안/추정으로 분리한다.

3. 사용자와 여정

KRDS의 첫 진입은 역할별로 나뉘며, 각 사용자는 다른 목적과 성공 기준을 가진다.

디자이너

Figma 라이브러리와 토큰, 컴포넌트, 패턴을 활용해 일관된 화면을 설계한다.

  • Pretendard GOV 서체 준비
  • Figma Community 파일 열기
  • Assets 검색과 variant 변경
  • 선명한 화면 모드/반응형 검수

개발자

HTML Component Kit과 토큰을 프로젝트에 설치하고 접근성 상호작용을 구현한다.

  • NPM/GitHub/CDN 설치
  • SCSS/CSS/JS 적용
  • 토큰 JSON to CSS variable
  • React/Vue 환경 연계

정부 관계자

적용 범위, 접근성, 디지털 포용, 적용 사례를 기준으로 사업 품질을 검수한다.

  • 표준형/확장형 이해
  • 접근성 체크리스트 확인
  • 적용 사례 검토
  • FAQ와 문의 채널 사용

컴포넌트 상세 설계-개발 계약서 역할 정의, 사용 기준, 변형, 상태, 접근성, 코드, 관련 패턴 Figma property, 상태명, CSS class가 대응된다.
패턴 상세 반복 과업 UI 조합과 사용자 여정 제공 과업, 포함 컴포넌트, 화면 구조, 예외, 접근성 과업 완료 흐름과 오류/확인 상태가 포함된다.

6. 컴포넌트 요구사항

컴포넌트는 카테고리 목록보다 상태, 모드, 반응형, 접근성, Figma property, 코드 상태명의 매트릭스로 관리해야 한다.

Identity공식 배너 / Masthead

공식 전자정부 서비스임을 식별한다. 포커스와 공식성 안내 텍스트가 필요하다.

Identity헤더 / Header

브랜드, GNB, 통합검색, 전체메뉴, 언어, 화면 설정을 제공한다.

Navigation건너뛰기 링크 / Skip link

키보드 사용자가 반복 영역을 건너뛰고 본문으로 이동하게 한다.

Navigation브레드크럼 / Breadcrumb

현재 위치와 상위 계층을 표시하며 current 상태가 보조기술에 전달되어야 한다.

Layout모달 / Modal

단일 과업 집중을 위해 사용하며 포커스 트랩, 초기 포커스, 닫기 후 복귀가 필요하다.

Layout탭 / Tab

상호배타적 콘텐츠 전환에 사용하며 tablist, tab, tabpanel 관계를 명확히 한다.

Action버튼 / Button

기능 실행 또는 상태 변경에 사용한다. 아이콘 버튼은 접근 가능한 이름이 필수다.

Selection라디오 버튼 / Radio button

상호배타적 단일 선택에 사용하며 그룹 레이블과 옵션 레이블을 제공한다.

Selection체크박스 / Checkbox

다중 선택 또는 독립 동의에 사용하며 선택 상태와 레이블이 명확해야 한다.

Feedback단계 표시기 / Step indicator

절차 진행 상태를 안내하며 현재 단계가 스크린 리더에서 확인되어야 한다.

Feedback토스트 / Toast

사용자 행동 결과를 임시 안내한다. 중요한 정보를 자동 소멸 메시지에만 담지 않는다.

Help툴팁 / Tooltip

짧은 부가 설명에만 사용하고, 필수 정보는 툴팁 안에만 숨기지 않는다.

Help음성지원 / TTS

주요 안내를 음성으로 읽는 보조 수단이며 재생 상태와 읽을 대상이 명확해야 한다.

Input텍스트 입력 필드 / Text input

레이블, 도움말, 오류 메시지, 필수 여부, 자동완성 속성을 제공한다.

Input파일 업로드 / File upload

허용 형식, 용량, 개수, 업로드 상태, 삭제, 재시도 흐름을 제공한다.

Mobile바텀시트 / Bottom sheet

모바일 하단 집중 패널로 사용하며 닫기, 포커스 이동, 드래그 핸들을 고려한다.

공통 상태 요구사항

상태 그룹 필수 상태 설계 기준
인터랙션 enabled, hover, pressed, focus, disabled focus 상태는 모든 조작 컴포넌트에 명시한다.
선택/확장 selected, expanded, collapsed, current 선택과 펼침 상태가 보조기술에 전달되어야 한다.
입력 empty, filled, required, readonly, error, success 오류는 색상만으로 전달하지 않고 필드와 연결한다.
모드 light, high-contrast, large, small 선명한 화면 모드와 반응형 모드에서 재검수한다.

9. 접근성/디지털 포용

공공 디지털 서비스의 품질은 기본 화면보다 접근성, 오류, 대기, 인증, 글자 확대, 고대비 같은 예외 조건에서 결정된다.

기준

KWCAG 2.2, WCAG 2.1/2.2, ARIA Authoring Practices Guide를 참고한다.

특화 기능

선명한 화면 모드, 언어 변경, 화면 크기 조정, 접근 가능한 미디어, 숨긴 콘텐츠, 음성지원.

필수 검수

키보드 조작, 포커스 순서, 접근 가능한 이름, 오류 연결, 시간 제한 조절, 상태 메시지.

화면/기능 체크 항목
검색포커스 이동, 결과 수 안내, 결과 없음 안내, 닫기
전체메뉴현재 위치, Esc 닫기, 배경 포커스 차단
입력 폼오류 요약, 필드별 오류 연결, 자동완성
로그인접근 가능한 인증, 초점 순서, 세션 연장
신청현재 단계 안내, 섹션 제목, 제출 전 확인
